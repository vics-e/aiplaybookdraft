About this tracker

A plain record of how this project has been checked before release, so anyone can see what was tested, what passed, what failed and what's still to do.

What's being checked

  • Manual Testing (38 checks): how the site looks, works and copes: layout, forms, browsers, speed and accessibility.
  • QA Release Checklist (29 checks): whether it's ready to go live: sign-offs, browsers and devices, and no serious bugs left.
  • Both lists come from Sage's QA checklists (Global Web Development, Confluence). Their wording is kept as written.

    How a check gets done

    1. Test itOn the live site, at the sizes and browsers it names.
    2. Record proofA screenshot or note, linked in Evidence.
    3. Fix if it failsChange the code, push it live.
    4. Re-testCheck again; the history keeps both results.

    Saving and sharing

    • Changes save automatically, in this browser only.
    • To share results, use Share & save → Download report.
    • To hand over editing, send the editable backup; the other person imports it.
    • The published version only changes when the project owner updates it.

    Why we QA

    • We find problems before the people using it do.
    • It proves it works on the browsers and devices people actually use.
    • Sign-off is based on evidence, not on someone's say-so.
    • Every fix becomes a lesson, so the next project starts with fewer problems.
